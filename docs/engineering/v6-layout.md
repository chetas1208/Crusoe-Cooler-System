## Layout (parametric, all coordinates derived from one generator config)
- Hall ≈ 36 m (X) × 22 m (Z) start size; derive final dims from collision extents, document changes.
- 5 rack rows `ROW-01..05`, 8 racks each = **40 selectable racks** (`rack` ids stable, row/slot encoded), row centerlines start z=[-8,-4,0,4,8], x≈7..29.
- 4 roads `ROAD-01..04` between adjacent rows (z≈[-6,-2,2,6]), clear width computed from rack extents + robot body + arm envelope (target 2.5–2.9 m, validate numerically; adjust hall/offsets if not).
- End cross-aisles (x≈5 and x≈31) connect all four roads (turnaround, docking, retreat). Mechanical/CDU bay at one end with CDU, pumps, strainers, isolation valves, sensors, tool/dock stations, plant boundary. No tank/pipe/label blocking turnarounds.
- Pipes crossing roads are elevated/in trays/chases; nothing hangs in the driving lanes; nothing penetrates racks/walls without a modelled penetration.
## Fleet
- **8 OUTRIG** `OR-01..08`, 2 per road (OR-01/02 road 1 … OR-07/08 road 4), distinct non-overlapping start/hold bays, collision-free poses; if a road is too narrow to pass, use time reservations / passing bays / opposite sectors. Default `EXTERNAL_ROBOTS_PER_CORRIDOR=2`; unsupported counts are validated/rejected. Navigation graph over roads + cross-aisles; body+arm envelope used for clearance; reservations prevent deadlock at aisle entrances and repair stations. Each road has ≥1 valid service/approach target (manifold panel, valve, strainer, hatch) with an approach pose.
- **10 INPIPE** `IR-01..10`: launch ports + serviceable bypass/inspection segments only (never rack cold-plate channels); ~2 per row only if real traversable segments exist, else staged at docks (truthfully). State = (segment_id, s_m, world pose from centerline, battery, mission, control_owner).
- **5 SENTINEL** `SEN-01..05`: virtual, no pose/mesh; shown in Agents only.
## Cooling network (graph first, then mesh)
- FWS: plant supply boundary → isolation/pump/header → CDU primary inlet → exchanger → CDU primary outlet → FWS return → plant return boundary. TCS: CDU secondary outlet → supply trunk → 5 row supply headers → 40 rack supply manifolds (valves/QDs) → rack thermal load (cold plates = resistance + heat load) → rack return manifolds → 5 row return headers → return trunk → CDU secondary return (TCS pump). FWS and TCS never share fluid nodes/edges; the CDU exchanger is a thermal coupling, not a pipe.
- Each node/edge: id, loop, centerline xyz, inner diameter, nominal direction, hydraulic component id, maintenance access (robot-service/external-only/not-serviceable), robot_passable. Render-only fittings must be flagged non-hydraulic.
- pandapipes: 5 row branches + 40 rack loads with correct boundaries; CompOpt: if 40 explicit racks is too heavy, use a documented aggregated thermal representation — never 40 invented temperatures. Quasi-steady hydraulics, labelled as such.
- Build-time and boot-time validator (fails tests): no dangling/unlabelled edges; every rack has a directed TCS supply→load→return→CDU path (all 40 by id); FWS supply+return reach CDU primary + plant boundary; FWS/TCS hydraulically disjoint; positive bore, length == centerline length, no zero-length/duplicate edges; mass balance per loop/junction within tolerance; perturbing a valve/branch changes the solver result and linked thermal state; flow arrows use signed solved flow.
