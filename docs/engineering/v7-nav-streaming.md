# V7 — freeze fix, progressive facility streaming, zero-LLM routing, true manual navigation (condensed; user's original text was cut at acceptance test 11)

Builds on V6 (5 rows × 8 racks, 4 roads, 8 OR + 10 IR + 5 virtual SEN). Priority: safe navigation + responsiveness > measurably lower browser workload > close-up detail > optional server-GPU WebRTC. No LLM, no Laya, no Neon query on the motion / render / lease-expiry critical path. Server stays authoritative; physics runs with the browser closed.

Instrument, don't guess: React reconciliation, draw calls/transmission passes, textures, useFrame closures, extra canvases, shader compile, asset decode, scene clones on selection, WS JSON volume, GC, raycast loops, overlays, server tick, sync sim calls. Measure cold/warm load, overview, zoom, chase, pipe POV, driving with 18 moving robots, repair, replay: p50/p95/p99 frame, CPU/GPU ms, long tasks, bytes, draw calls/tris, decoded geometry+texture memory, control→pose latency. ## 1. Progressive geometry (Agent B + small backend manifest piece)
Default = server-prepared immutable tiles, browser GPU renders. Zones follow V6 topology: ROW-0n bays, ROAD cells, plant/CDU, trunks, docks, pipe-segment neighbourhoods (segment ahead/behind + junction). LOD0 shell (instanced racks, line pipes, route corridors; always present, ≤~1.5–3 MB, procedural from topology until assets exist — no fake manifest), LOD1 row/road, LOD2 rack/repair zone, LOD3 selected robot/contact zone only. Screen-space-error driven with hysteresis, AbortController, keep lower LOD visible while higher loads, byte-budgeted predictive prefetch (camera/robot velocity), LRU with separate encoded/decoded/GPU quotas and explicit dispose, cache keyed by layout_hash/topology_revision/manifest_version/tile_hash. Feature id → canonical entity id stable across LODs; robots are a dynamic layer (refs/instanced transforms, no React re-render per pose). Manifest: `GET /api/v1/facilities/{id}/render-manifest?rev=`, assets `/assets/sha256/{hash}` immutable-cached. 3D Tiles only if it benchmarks better. Failure policy: decode fail → lower LOD; OOM → reduce quality/evict; disconnect → stale banner + safe hold. Quality: Auto/Performance/Balanced/High/4K (internal scale separate from output resolution); never change sim or robot count; no new top-level tab. Budgets are targets to tune: LOD0 TTI ≤2.5 s, cached low/mid LOD ≤100 ms, high LOD p95 ≤400–800 ms warm, no >50 ms long tasks while navigating, command ack ≤150 ms p95 on a near network.
## 2. Navigation (Agent A; extend what V6 built, don't rewrite)
Two graphs from validated geometry: G_ext (roads, end + mid cross-aisles, passing/yield/service/parking/dock nodes; edges with centerline, width/height, min turn radius, direction, classes, grade, speed, capacity, conflict sets) and G_in (robot-passable pipe segments only: bore, bend/tee limits, access/isolation, entry/exit ports; never CDU exchanger or rack cold plates; recovery ports so no robot is stranded). Poses: edge_id + arc_length + lateral offset + world xyz + quaternion; smooth feasible splines at junctions (no teleport). Planning without LLM: A*/Dijkstra with class/access/closure/energy/turn-clearance filters + time-aware reservation table (prioritised planning, SIPP-style safe intervals if needed), bounded expiry, idempotent owner; hot state in the world worker's memory, Neon only on change (transactional), single active scheduler per run (fencing). Regulated pure-pursuit-style follower with accel/decel limits and a local emergency brake independent of the scheduler. Deadlock: wait-for cycle detection → priority/reroute/back into passing bay/expire/preempt parking; if unsolvable, safe stop with exact reason. Incident assignment = feasible-robot scoring (reach, tools, battery, ETA incl. traffic, existing mission, urgency), recorded route_plan_id/ETA/actual arrival. Reasons: NO_ACCESS, TURN_RADIUS, EQUIPMENT_BLOCK, RESERVATION_CONFLICT, PRESSURE_UNSAFE, BATTERY, PIPE_CLEARANCE.
APIs: `GET /runs/{id}/navigation/graphs?kind=`, `GET .../navigation/reachability?robot_id&target_id`, `POST .../robots/{id}/route/{plan,commit,cancel}` (commit = optimistic on graph/traffic revision, not tick), existing lease/drive/release; WS events robot.route_planned/committed/replanned, robot.arrived, traffic.reservation/yield/blocked, robot.drive.accepted/rejected, asset.manifest_changed (all with run_id, seq, sim_tick, graph_revision). Neon (Alembic): facility_layouts, render_manifests, nav_nodes, nav_edges, robot_routes, traffic_reservations, robot_poses (sampled), render_stream_sessions; pin topology/graph versions on runs; forks never mutate parents; no per-frame writes.
## 3. Manual control (A backend, B UI)
Take Control = exclusive lease; other robots, physics and monitoring continue. Two human modes, both deterministic: low-level throttle/steer projected onto the feasible route tube with swept-collision checks (W/S along edge, A/D = legal branch/lane only, Space brake), and destination mode (click reachable service point → show reserved route + ETA, pause/override/reroute). OUTRIG vs INPIPE controls per table in the user's text (INPIPE: branch selector at junctions, no strafing through walls). Commands carry lease_id, monotonic command_seq, duration_ms, graph_revision, intent, branch — never equality with the world tick; 15–30 Hz intents, 10–20 Hz pose for the driven robot, lower for the rest; blur/hidden/lost heartbeat/expiry → zero velocity + SAFE_HOLD, reacquire lease explicitly; manual override releases/renegotiates reservations, priority is bounded (never starves emergencies); renderer only interpolates authoritative poses and never invents motion on rejection/disconnect. Camera: front/rear/side/chase/orbit/tactical, parented to the real robot frame.
## 4. Update-rate decoupling + interest management (A+B)
Physics tick, pose stream (5–20 Hz adaptive), agent decisions (event-driven), browser rAF are independent. Subscription carries run_id, visible_zone_ids, selected entity, camera mode, rate budget; server prioritises selected robot, throttles/event-only for the rest; all 18 robots keep simulating with no subscriber. Binary/delta protocol or worker decode only if profiling shows JSON is the problem.
## 5. Optional remote inspection view (gated; last)
Probe chain: GPU → renderer → NVENC/codec → secure WebRTC/TURN → capacity → measured latency better than local. If any gate fails, ship local LOD and document. Never auto-enable; show Local/Remote status; one physics worker only.
